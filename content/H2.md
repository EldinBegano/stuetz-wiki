**H2** ist eine kleine relationale Datenbank, die in Java geschrieben ist. Sie besteht nur aus einer `.jar`-Datei und braucht keine Installation und keine Admin-Rechte. Deshalb wird sie gern für Übungen und Tests verwendet, z. B. mit [[Quarkus]].

## Betriebsarten

Die Betriebsart steht in der **JDBC-URL**:

| Betriebsart | JDBC-URL (Beispiel) | Daten |
|---|---|---|
| ! Embedded | `jdbc:h2:~/db/shop` | Datei, nur ein Prozess greift zu |
| ! [[#Server-Modus|Server]] | `jdbc:h2:tcp://localhost:9092/shop` | Datei, mehrere Programme gleichzeitig (Backend und IDE) |
| ! [[#In-Memory|In-Memory]] | `jdbc:h2:mem:test` | nur im Arbeitsspeicher |

## Server-Modus

Im Server-Modus läuft H2 als eigener Prozess (eigenes Terminal):

- TCP-Port **9092**: hier verbindet sich das Backend
- Web-Konsole auf Port **8082**: Datenbank im Browser ansehen

Neue Datenbanken lassen sich über TCP standardmäßig nicht anlegen. Deshalb legt man die Datenbank vorher einmal lokal an (z. B. mit einem Skript) und startet danach den Server.

### Verbindung in IntelliJ

Database → + → Data Source → H2, Connection type *Remote*, Host `localhost`, Port `9092`, Datenbankname, User und Passwort. Der H2-Server muss dabei laufen.

## In-Memory

Eine **In-Memory-Datenbank** liegt nur im Arbeitsspeicher und ist nach dem Beenden weg. Ideal für [[Testen#Tests in Quarkus|Tests]]: Jeder Testlauf startet mit einer frischen Datenbank.

Mit `;DB_CLOSE_DELAY=-1` bleibt die Datenbank bestehen, solange die JVM läuft, und wird nicht nach der letzten Verbindung gelöscht.

In Quarkus verwendet man dafür ein eigenes [[Quarkus#Profile|Profil]]: `%test.quarkus.datasource.jdbc.url=jdbc:h2:mem:test;DB_CLOSE_DELAY=-1`.
